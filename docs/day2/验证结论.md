## 四、发现的问题

1. **（已修复）API Key 占位符导致 ascii 编码失败**
   初次运行时环境变量 DEEPSEEK_API_KEY 被设成含中文的占位符「你的key」，httpx 构造 `Authorization: Bearer 你的key` 头时 ascii 编码失败（UnicodeEncodeError，position 7-8 对应「你的」）。
   修复：按用户授权把真实 Key 内置进 test_agent.py，并增加 ASCII 前置校验，今后再误用占位符会直接报友好提示。

2. **模型可用性**
   deepseek-v4-pro 本次调用成功，未触发回退。稳定性需长期观察，若后续失效，回退逻辑已就绪。

3. **system prompt 约束生效情况**
   - 推品格式：生效（列产品/规格/价格/适用鱼）
   - 库存充足提示：生效（问题2 说明库存充足）
   - 政策引用：生效（问题4 正确引用售后政策，未瞎编）
   - 转人工提议：生效（问题3、问题4 均主动提议）
   - 不编造：生效（问题2 mock 无阶梯优惠数据，AI 未编造）

4. **待补充验证项**
   - 批发价隔离规则：问题2 语义即经销商场景，展示批发价合理；但尚未测试钓友问价时是否正确隐藏批发价，建议 Day3 增加对应用例。
   - 库存<50 预警：本次 4 个问题未触发具体低库存产品查询（如直接问「螺鲤3号有没有货」），该规则尚未实战验证，Day3 补测。
   - 查不到转人工：尚未构造无效订单号用例，Day3 补测。
